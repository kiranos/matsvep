# Production recipe processing and time provenance

Run seeding, ingredient normalisation, feature derivation and deduplication as one repeatable CLI pass under the `matsvep` account after the first full crawl. Hold the same MySQL advisory lock used by the crawler for the entire pass. Existing admin corrections in the unknown-ingredient queue, feature override table, duplicate review queue and manual dish-group membership remain authoritative. The operator starts processing manually after checking the crawl service; no timer starts this potentially long pass automatically. Reports live in `server/var/` and include time coverage before and after derivation.

Add `recipe.total_time_source` with `given`, `estimated` and `unknown` values. Backfill existing non-null times as given. When a recipe lacks source total time, estimate by summing explicit step durations using Swedish unit forms from seed data. Keep a still-unknown time neutral for DayFit's soft cap and effort's time component. A JSON-LD Recipe with ingredients but no instructions remains a recipe with zero steps so the quality report can surface it; the saved production page demonstrates this variant. The other three saved HTTP 200 pages parse under the current parser and remain local diagnostics.

Passive waiting phrases live in `server/seeds/passive_time_phrases.csv`; durations tied to them do not contribute to estimated cooking time. Reprocessing updates previously estimated values and reports the number changed.
