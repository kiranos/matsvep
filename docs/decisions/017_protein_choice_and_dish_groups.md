# Protein choice and dish groups

The 448-recipe pilot had 82 of 188 dinner candidates without a main protein. Thirty baseline examples and their main ingredient lines are kept in a local, gitignored review report. Add missing meat, fish, legume and pasta aliases through seed data. Title protein evidence takes precedence; otherwise the largest convertible gram amount wins, with the first main ingredient line breaking ties. Cheese and eggs supply `vegetarian` only for confidently vegetarian dishes, and a confidently vegetarian dinner can use that code without a named plant protein. Dinner eligibility for an unclassified meal type still requires actual protein or carb evidence, so this fallback does not admit unrelated snacks. The rerun leaves 13 of 222 dinner candidates without a protein (5.9%).

Canonical URL equality identifies copies directly. Matching normalized titles and non-staple main-ingredient Jaccard overlap use the configured 0.95 automatic-merge and 0.80 review thresholds. Metadata tolerances are configured separately. The more complete parse survives, with source priority and ID as tie-breakers. The losing recipe is marked inactive and points to the survivor; its raw record remains, while source links and ingest references move to the survivor. The duplicate review queue retains admin decisions. Only active recipes enter future candidate pools and automatic dish grouping.

Dish cores are reduced using seeded title words. Variants with the same core and protein and configured ingredient overlap share a dish group. Manual overrides are left alone. The pilot has no additional copies to merge and one two-recipe dish group; the pass is repeatable without changing those counts.
