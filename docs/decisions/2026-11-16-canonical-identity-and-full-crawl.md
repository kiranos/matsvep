# Canonical recipe identity and resumable full crawl

The 500-URL pilot classified 448 pages as recipes, 51 as non-recipes and one as gone. Of the fetched recipe URLs, 134 were nested paths. We therefore keep sitemap discovery as the main route, but identify each recipe by the same-host canonical link in the page, or by JSON-LD `url` when the link is absent. The fetched URL remains a source link. A queued URL whose source link already identifies a stored recipe is marked `duplicate` without a request. An unseen alias must be fetched once before its canonical identity can be known.

Migration 005 adds the terminal `duplicate` ingest status and a `crawl_discovery` marker. The full crawl uses the locally saved sitemap and writes the marker only after discovery completes. An interrupted discovery can repeat idempotently. The operator uses a normal local database, a six-hour default run limit, and reruns the script on later nights. The crawler keeps the pilot's bounded retry wait and reports pending retries for a later run. Reports contain counts and URLs only. Existing pilot snapshots are read to count nested-to-root canonical aliases without live requests or schema changes to old recipe rows.
